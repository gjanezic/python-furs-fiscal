# AGENTS.md

This file provides guidance to agents when working with code in this repository.

- This is the **2.0 rewrite**. The 1.x `FURSInvoiceAPI`/`FURSBusinessPremiseAPI`/`Connector`/`base_api.py`/`exceptions.FURSException` API is gone. Read `README.md` "Migrating from 1.x" before making 1.x-shaped assumptions.
- Official primary sources for FURS/eDavki technical specifications are the technical-specifications page at https://edavki.durs.si/edavkiportal/openportal/CommonPages/Opdynp/PageD.aspx?category=dpr_teh_spec and the direct PDF technical documentation at https://www.datoteke.fu.gov.si/dpr/files/TehnicnaDokumentacijaVer3.2.pdf. For any task involving technical specifications, request structures, certificates, signing, eDavki/FURS communication, or related integrations, consult these sources first, verify the information is current, and clearly separate facts from official documentation from agent inferences or recommendations.
- A local copy of the FURS v3.2 PDF is stored at `specs/TehnicnaDokumentacijaVer3.2.pdf`, with a searchable `pdftotext -layout` extract at `specs/TehnicnaDokumentacijaVer3.2.txt` and regeneration notes in `specs/README.md`. Use the local text extract for fast searches, but verify currency against the official page/PDF before relying on it.
- The official JSON schemas live at `specs/schemas/FiscalVerificationSchema.json` and `specs/schemas/FiscalVerificationSchemaBatch.json`; pydantic models in `furs_fiscal/models.py` mirror them and the replay tests in `tests/test_replay.py` validate the library output against them.
- Run tests with `pytest` (configured via `pyproject.toml`). 156 tests across `tests/test_models.py`, `tests/test_zoi.py`, `tests/test_transport.py`, `tests/test_api.py`, `tests/test_replay.py`, `tests/test_real_cert.py`. Two of those (`test_live_echo_against_furs_test_endpoint`, `test_live_register_business_premise_against_furs_test_endpoint`) hit the FURS test endpoint and are gated behind `FURS_LIVE_TEST=1`; the default `pytest` run is fully offline and shows them as skipped. `tests/conftest.py` builds an in-memory PKCS#12 client cert via `cryptography.serialize_key_and_certificates` for transport/API tests. Surveillance tests in `test_transport.py::test_furs_tls_cipher_list_rotation_surveillance` and `test_real_cert.py` yellow-warn ahead of the FURS production cipher list rotation (sec. 6.2.2 active until 2026-05-12) and ahead of FURS-published cert expiries; fail red once the date passes — see `make check-cert-expiry` and the maintenance notes in `Makefile`.
- Packaging is `pyproject.toml` (PEP 621, hatchling backend). Python 3.10+ minimum. Runtime deps: `cryptography`, `PyJWT`, `httpx`, `pydantic`. Dev deps: `pytest`, `jsonschema`, `hypothesis`. **Do not** add `pyOpenSSL`, `pytz`, `requests`, or `setup.py` back — they were intentionally removed.
- Core flow: `FURSClient` (in `furs_fiscal/api.py`) takes a typed pydantic model (`Invoice` / `SalesBookInvoice` / `BusinessPremise`), calls `wrap_*` from `models.py` to build the wire envelope, then delegates to `Connector.post` (in `transport.py`) which signs as JWS, posts via `httpx.Client`, decodes the response token, and converts `Error` envelopes into the granular exception hierarchy. Convenience methods `submit_invoice_subsequent(invoice)` (sets `SubsequentSubmit=true` per R_3.13) and `close_business_premise(premise)` (sets `ClosingTag='Z'` per P_7.0) wrap the matching submit methods with `model_copy` so callers don't have to rebuild the payload. The unsigned `client.echo(message="furs")` is a separate path through `Connector.echo` (plain JSON `{"EchoRequest": ...}` → `{"EchoResponse": ...}`, no JWS, no retry — by design, since echo IS the connectivity probe).
- Retry policy: `Connector(retries=N, retry_backoff=0.5)` (also exposed on `FURSClient`) enables exponential-backoff retries on transient failures only — `httpx.RequestError`, HTTP 5xx, HTTP 408/429, and `FURSResponseError` subclasses with `is_retryable=True` (currently only `FURSSystemError` / S100). Schema (S001/S002), signature (S003), certificate (S004/S005/S007/S008), business-premise (S006), and generic 4xx are NOT retried — they're deterministic and would just repeat. Default `retries=0` keeps the legacy single-attempt behaviour. The retry classification helper is `transport._is_retryable_connection_error`; extend `_RETRYABLE_CONNECTION_CODES` if FURS adds a transient transport-side code.
- `Connector` loads the `.p12` client cert into an `ssl.SSLContext` via `_load_ssl_context_with_client_cert`. PEMs are written to `mkstemp` (mode `0600`) only for the duration of `load_cert_chain`, then unlinked. There is a brief on-disk window during load — fully memory-only mTLS is not possible with stdlib `ssl` since `load_cert_chain` requires file paths. Do not reintroduce the 1.x `NamedTemporaryFile(delete=False)` pattern that left PEMs on disk for the connector's lifetime.
- TLS verification defaults to **enabled** (`verify_tls=True`, system CA store). Disabling it (`verify_tls=False`) emits `FURSTLSVerificationDisabledWarning`. For production, prefer pinning to the SIGOV-CA bundle (`verify_tls="/path/to/sigov-ca.pem"`).
- TLS protocol/cipher pinning lives in `_load_ssl_context_with_client_cert` and applies regardless of the `verify_tls` value: `ctx.minimum_version = TLSv1_2` (spec sec. 2 disables 1.0/1.1) and `ctx.set_ciphers(FURS_TLS_CIPHERS)` with `FURS_TLS_CIPHERS = "ECDHE+AESGCM+aRSA:DHE+AESGCM+aRSA"` — the intersection of the spec sec. 6.2.1 (test) and 6.2.2 (production) AEAD-RSA lists. `+aRSA` drops unreachable ECDSA/DSS variants. TLS 1.3 ciphers are configured by OpenSSL separately and are not affected by `set_ciphers`. Do not relax these without a spec citation.
- FURS response signature verification defaults to `verify_furs_response='x5c-untrusted'` (verifies signature against the cert in the JWS `x5c` header, validity window checked, chain not validated, emits `FURSResponseChainNotVerifiedWarning`). The MITM-resistant mode is `verify_furs_response=True` with a pinned `furs_response_public_key`.
- All datetimes flowing into models, ZOI, or `prepare_printable` MUST be timezone-aware. They are auto-converted to `Europe/Ljubljana` (via `models.LJUBLJANA = ZoneInfo("Europe/Ljubljana")`) before formatting. Naive datetimes raise `ValueError`/`pydantic.ValidationError`.
- Datetime/date wire formats: `IssueDateTime`, `ReferenceInvoiceIssueDateTime`, and Header `DateTime` use `YYYY-MM-DDTHH:MM:SS` (no `Z`). `ValidityDate`, `SalesBookInvoice.IssueDate`, and `ReferenceSalesBookIssueDate` use `YYYY-MM-DD`. These are encoded by the `FURSDateTime`/`FURSDate` annotated types in `models.py`.
- All amount fields accept `Decimal`, `int`, or `str` only — `float` is rejected by `_coerce_to_decimal` to eliminate IEEE-754 footguns. Amounts that cannot round-trip through `float64` (i.e. close to the schema's exclusive ±100T limit) are also rejected by `_check_amount` so the on-the-wire payload always matches the ZOI input string.
- Wire integer values (cadastral/building numbers): kept as `int` per the official JSON samples (`"CadastralNumber": 365`). Amounts/tax rates: serialized as `float` via `PlainSerializer` even when whole-valued (matches FURS samples like `"TaxRate": 22.0`).
- Pydantic models use `extra='forbid'` to mirror the schema's `additionalProperties: false`. Mutual-exclusion rules (operator local vs foreign, BPIdentifier oneOf, VendingMachine address-XOR-geolocation, SoftwareSupplier TaxNumber-XOR-NameForeign) are enforced via `@model_validator(mode='after')`.
- ZOI lives in `furs_fiscal/zoi.py` as pure functions; no Connector or HTTP dependency. `FURSClient.calculate_zoi` is a thin convenience wrapper that injects the connector's loaded private key. `prepare_printable` is `@staticmethod` on the client.
- Per-record batch errors raise `FURSBatchError` with `.record_errors: dict[int, FURSResponseError]` and `.successes: dict[int, dict]` so callers can persist the EORs of records that succeeded without resubmitting.
- FURS error-code routing: spec sec. 4 codes are mapped to specific subclasses by `_ERROR_CODE_MAP` + `from_furs_error` in `furs_fiscal/exceptions.py`. Current mapping: S001/S002 → `FURSSchemaError`, S003 → `FURSSignatureError`, S004/S005/S007/S008 → `FURSCertificateError` (unknown / tax-mismatch / revoked / expired digital cert), S006 → `FURSBusinessPremiseError`, S100 → `FURSSystemError`; anything else → `FURSServerError`. Lookup is case-insensitive (production has been observed sending lower-case `s002`). When adding a new code, update **both** `_ERROR_CODE_MAP` and the parametrized `test_from_furs_error_maps_spec_section_4_codes` in `tests/test_transport.py`.
- Retry-decision attribute: `FURSResponseError.is_retryable` defaults to `False`; only `FURSSystemError` (S100) overrides it to `True`. Retry middleware should branch on this flag instead of pattern-matching on the code so future transient codes can be added in one place.
- The `demos/` directory still contains 1.x-shaped scripts and is not updated for 2.0; treat it as historical and prefer the README quick-start as the reference example.

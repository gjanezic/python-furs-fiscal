# Project Coding Rules (Non-Obvious Only)

- For implementation work involving FURS/eDavki technical specifications, request structures, certificates, signing, communication, or related integrations, first consult the official technical-specifications page at https://edavki.durs.si/edavkiportal/openportal/CommonPages/Opdynp/PageD.aspx?category=dpr_teh_spec and the direct PDF technical documentation at https://www.datoteke.fu.gov.si/dpr/files/TehnicnaDokumentacijaVer3.2.pdf; verify currency and distinguish official-documentation facts from implementation recommendations.
- Use `specs/TehnicnaDokumentacijaVer3.2.txt` as the repository-local searchable extract of the FURS v3.2 PDF; regenerate with `pdftotext -layout specs/TehnicnaDokumentacijaVer3.2.pdf specs/TehnicnaDokumentacijaVer3.2.txt` when the PDF changes. The official JSON schemas at `specs/schemas/FiscalVerificationSchema*.json` are mirrored 1:1 by pydantic models in `furs_fiscal/models.py`; **schema and models must stay in sync**.
- Pydantic v2 only catches `ValueError` and `AssertionError` raised inside `BeforeValidator`/`AfterValidator`. **Do not raise `TypeError`** — it leaks through as a non-`ValidationError`. Use `ValueError` for all validator failures.
- All amount fields must accept only `Decimal`/`int`/`str` and reject `float` via `_coerce_to_decimal`. The IEEE-754 round-trip check in `_check_amount` (`Decimal(repr(float(quantized))) != quantized`) prevents silent cent-loss at the schema's upper bound; do not relax it.
- Wire serialization rule: amounts/tax rates serialize as `float` via `PlainSerializer` even for whole values (matches FURS samples like `"TaxRate": 22.0`). Cadastral/building/section numbers serialize as `int` (matches `"CadastralNumber": 365`). Do not unify these.
- Pydantic models use `extra='forbid'` and field aliases with exact FURS casing (`TaxNumber`, `BusinessPremiseID`, `ProtectedID`, etc.). When adding fields, use `Field(alias="OfficialKey")` so snake_case attribute names map to the wire keys.
- All datetimes flowing into models / ZOI / `prepare_printable` must be timezone-aware. The `FURSDateTime`/`FURSDate` annotated types in `models.py` auto-convert to `Europe/Ljubljana` (`models.LJUBLJANA = ZoneInfo("Europe/Ljubljana")`) before formatting. Naive input raises `ValidationError`/`ValueError`. Do not add a "naive means local" fallback — that was the 1.x footgun.
- `IssueDateTime`, `ReferenceInvoiceIssueDateTime`, and Header `DateTime` use `YYYY-MM-DDTHH:MM:SS` (no `Z`). `ValidityDate`, `SalesBookInvoice.IssueDate`, and `ReferenceSalesBookIssueDate` use `YYYY-MM-DD`. Both formats are produced by `_serialize_datetime`/`_serialize_date` in `models.py` — do not hand-format dates elsewhere.
- ZOI input validation in `furs_fiscal/zoi.py` is intentionally redundant with the pydantic validators (it does not import the models to stay zero-dependency for offline POS use). When changing identifier/amount rules, update both `models.py` AND `zoi.py` together.
- Mutual-exclusion / `oneOf` schema rules are enforced in pydantic via `@model_validator(mode='after')` (`Invoice` operator fields, `BPIdentifier`, `VendingMachine`, `SoftwareSupplier`). Adding new constraints belongs there, not in `FURSClient`.
- `Header` has `default_factory` for `MessageID` (uuid4) and `DateTime` (`datetime.now(LJUBLJANA)`). The `wrap_*` envelope helpers in `models.py` instantiate request envelopes with a fresh Header by default — only pre-build a Header when retrying with the same MessageID for FURS-side dedup.
- Endpoint paths are constants in `furs_fiscal/api.py` (`PATH_INVOICE` etc.). Do not hard-code them at call sites.
- Per-record batch error handling in `FURSClient._collect_record_replies` raises `FURSBatchError` only after walking every record, so successes are always preserved on the exception (`exc.successes`). Maintain this all-or-nothing-AFTER-walk pattern when extending.
- `FURSClient` is a context manager; `__exit__` calls `Connector.close()` which closes the underlying `httpx.Client`. After exit, `client._connector._client.is_closed` is True. Tests assert this.
- Mock httpx for tests via `httpx.MockTransport(handler)`. The mock client must still get a `base_url` (set to `FURS_TEST_ENDPOINT`); `httpx` requires it to resolve relative paths.
- `specs/examples/*.txt` are JWS tokens published by FURS; `tests/test_replay.py` decodes them and asserts our wire output matches structurally (modulo the per-message Header). When changing serialization, run replay tests first — they are the strongest skladnost gate.
- Adding a new FURS error code (spec sec. 4): edit `_ERROR_CODE_MAP` in `furs_fiscal/exceptions.py` AND the parametrized list in `tests/test_transport.py::test_from_furs_error_maps_spec_section_4_codes` in the same change. The dispatch is case-insensitive (`code.upper()`); production has been observed sending lower-case `s002`, so keep the `("s002", FURSSchemaError, False)` row when refactoring. New transient/server-side codes should subclass `FURSResponseError` and set `is_retryable = True` at class scope (mirror `FURSSystemError`); persistent failures inherit the default `False`.
- TLS protocol/cipher pinning lives in `_load_ssl_context_with_client_cert` and is enforced unconditionally (even with `verify_tls=False`). The cipher constant `FURS_TLS_CIPHERS` is the intersection of spec sec. 6.2.1 / 6.2.2 AEAD-RSA lists; the surveillance test `test_furs_tls_cipher_list_rotation_surveillance` fails red after 2026-05-12 to force a re-verification. When refreshing: read sec. 6.2 of the latest `TehnicnaDokumentacijaVer*.pdf`, recompute the test∩prod intersection, update `FURS_TLS_CIPHERS` AND the comment above it AND `FURS_PROD_CIPHER_LIST_ACTIVE_UNTIL` in the test. Do not bypass the surveillance by widening the date without re-verifying the suites.
